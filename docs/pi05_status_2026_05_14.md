## ❌ 卡在 JAX → PyTorch conversion 这一步

**根本问题**：`convert_jax_model_to_pytorch.py` 的依赖矩阵很难凑齐。
- openpi pin: `jax==0.5.3, flax==0.10.2, orbax==0.11.13`
- mirrors.ivolces.com 上**没 flax==0.10.2**（只有 0.11.0/0.12.7）
- jax 0.5.3 + flax 0.11.0 不兼容（API breaking change）
- 公网（pypi.org）从 dev pod / 本机都不通

**已尝试**：
1. dev pod 装 jax 0.5.3 + flax 任意版 → flax 0.11+ 用了 jax 0.10+ 才有的 API
2. 本机创 conda py3.11 env → pip 装 flax 0.10.2 timeout
3. 跨机器组合 → 都卡在 pypi 不通

## 三条路径（你来选）

### A. 在能上 pypi 的网络换镜像装 flax 0.10.2（最干净）
找一台能 pypi 直连的本机（你笔记本？），按 openpi requirements.txt 装一遍，
跑完 conversion 后只 push 7GB PyTorch ckpt 到 dev pod。

### B. 改用 pi0_libero（pi0，不是 pi0.5）
pi0 是更老的 model，依赖可能更宽容。HF 上 `lerobot/pi0_libero` 也是公开 ckpt。

### C. 不要 conversion，直接在 dev pod 用 JAX 推理
openpi 同时支持 JAX path（不需要 PyTorch 转换）。我们的 adapter 改成
"forward via JAX, return numpy logp" → 但失去 backprop 能力，DPO/GRPO 不能跑，
只能做 SFT eval。当 pi0.5 paper baseline 验证用足够，但 paper §4.2 第二行
DPO/GRPO 列空着。

## 建议

**短期**：选择 **C 方案**（JAX-only inference），先把 paper §4.2 pi0.5 SFT
eval 完成（4 cell × 5 trial）—— paper 报 pi0.5 spatial 98.8 / object 98.2 /
goal 98.0 / long10 92.4，我们重现一下作为基线就行。DPO/GRPO 列写 "JAX
weight conversion deferred to future work"。

**中期**：从你笔记本（公网通）按 openpi 标准 requirements 装环境，跑
conversion，得到 PyTorch ckpt 后再续 DPO/GRPO。
